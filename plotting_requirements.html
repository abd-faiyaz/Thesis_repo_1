1b. Two scan types — which data for which plot

Run the same eval APK set twice on POCO F3. Tag each pull with session.cascade_enabled (or separate output folders).

Scan type Config What it measures
A — All-models (ablation) UI: Ablation (all models) → cascade_enabled=false Every model runs on every APK. Fair per-model latency, CPU, memory, time-weighted battery split.
B — Cascade (deployed) UI: Cascade (deployed) → clear dedup → cascade_enabled=true Early exit; cascade.models_skipped populated. Median totals.wall_ms for CSV Comments.

Offline metrics (ACC, F1, ROC-AUC) always come from PC test JSON — neither scan type.

Template / deliverable Scan A (all-models) Scan B (cascade) Notes
apk_size_vs_detection_time.png ✅ Use ✗ Compares per-model stage time vs APK size; skipped stages have no fair point.
Stacked bar (6fd97139-…png) ✅ Use ✗ Needs parse_ms + vectorize_ms + inference_ms for every bucket × model.
plot3_accuracy_vs_ram.png ✅ Use ✗ Y = offline F1; X = median per-model memory — requires all models to have run.
plot4_accuracy_vs_latency.png ✅ Use ✗ Same as plot3; one comparable latency point per model.
sample_model_vs_accuracy_resources.png ✅ Use ✗ CPU / RAM / battery columns need every model on every APK (battery via time-weighted session split).
performance_res_usage_tradeoff_plot.jpeg ✅ Use Optional 2nd series Primary Pareto uses per-model worst-case cost (scan A). Optional: overlay cascade average end-to-end point for “deployed” policy.
CSV — ACC, F1, ROC-AUC — — Offline test JSON only.
CSV — CPU, Memory, Total Time (Avg) ✅ Use ✗ for per-model rows Per-model medians from stages[] where status=ok.
CSV — Battery ✅ Use Alt. column Scan A: time-weighted split of session.battery.charge_counter_uah_used. Scan B: same formula but skipped models → 0 (deployment story only).
CSV — Total Time (deployed) ✗ ✅ Use Put median totals.wall_ms in Comments or a second “Cascade avg” column — not mixed with per-model ablation times.
Bonus: exit-tier / skip-rate chart ✗ ✅ Use Not in supervisor templates; thesis-only from cascade.exit_tier, models_skipped.
Rule of thumb: All Illustrations_templates plots and the CSV resource columns match Scan A. Scan B is for deployed latency, cascade exit rates, and optional “production cost” commentary — not for fair model-vs-model scatter or stacked timing charts.

VariableTypical pathOne-line meaning
model_idrootCanonical model bundle identifier.
domainrootFeature domain ID used on Android (stages[].domain).
splitrootWhich data partition was evaluated (test, temporal_holdout, etc.).
n_samplesrootNumber of APKs in the evaluated split.
metrics.accuracymetricsFraction of correct benign/malware classifications on the test split.
metrics.f1metricsHarmonic mean of precision and recall (primary detection-performance metric for plots).
metrics.roc_aucmetricsArea under ROC curve — ranking quality independent of a single threshold.
metrics.precisionmetricsFraction of predicted malware that are truly malware.
metrics.recallmetricsFraction of true malware correctly detected (sensitivity).
thresholdrootProbability cutoff used for hard class decisions in reported metrics.
confusion_matrixroot2×2 [[TN, FP], [FN, TP]] counts for the test split.
