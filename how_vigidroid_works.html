How VigiDroid Works

On-device APK scanner: 5 models run on each APK, scores and timings are logged. Simple overview — no deep internals.

Big picture: two places

flowchart LR PC["🖥️ PC — Python\nTrain & export"] Phone["📱 Phone — VigiDroid\nScan APKs"] PC -->|"model.onnx + config files"| Phone Phone -->|"metrics JSON"| PC

Models are trained on the PC, copied into the app as ONNX files, then run on the phone when you scan.

Models in the app today

XGBoost Manifest + DEX tokens active
1D-CNN Last 1024 APK bytes active
BM1 mlp_header Dex header only (104 nums) active
Pattern A Header + manifest BoW active
Pattern B Dual branch fused ONNX active

5 models total. XGBoost + CNN feed the main combined verdict (weighted average) shown in the results table. BM1, Pattern A, and Pattern B are separate thesis scores — logged only; they do not change the CNN/XGB verdict.

What each model reads from an APK

ModelInput (simple)Output
XGBoost Permissions, intents, DEX structure → 2500 flags Malware score 0–1
1D-CNN Last 1024 raw bytes of the APK file Malware score 0–1
BM1 mlp_header All classes*.dex headers summed → 104 numbers Malware score 0–1
Pattern A Dex header (104) + manifest permissions/intents → 4381-d BoW Malware score 0–1
Pattern B Same inputs as Pattern A; fusion is inside ONNX (MLP + ASCNN branches) Malware score 0–1

Full scan workflow (what happens when you tap Start)

flowchart TD A[You tap Start scan] --> B[ScanService starts] B --> C[Find all .apk in Download folder] C --> D{Any APKs?} D -->|No| E[Show: no APKs found] D -->|Yes| F[For each APK...] F --> G[Run XGBoost pipeline] F --> H[Run 1D-CNN pipeline] F --> I[Run BM1 mlp_header] F --> N[Run Pattern A] F --> O[Run Pattern B] G --> J[Combine XGB + CNN score] H --> J I --> K[Log all scores + timings] N --> K O --> K J --> K K --> L[Show result in app table] K --> M[Append to all_scan_metrics.json] F --> F

Inside one APK (visual)

APK file (in Download/) │ ├─► XGBoost path open ZIP → manifest + all classes*.dex → 2500-d vector → ONNX → score₁ │ ├─► 1D-CNN path read last 1024 bytes → ONNX → score₂ │ └─► ensemble = weighted mix of score₁ + score₂ → shown as main verdict │ ├─► BM1 path dex headers summed → 104 floats → ONNX → score₃ (logged separately) │ ├─► Pattern A path dex header + manifest BoW → ONNX → score₄ (logged separately) │ └─► Pattern B path same features as A → fused ONNX → score₅ (logged separately)

Where model files live

Built into the app (assets):

  • assets/bytecnn_basemodel_2020.onnx — CNN
  • assets/mh1m_2500_rp_XGBoost.onnx + feature list — XGBoost
  • assets/models/mlp_header/ — BM1 ONNX + normalization + parity samples
  • assets/models/pattern_a_combined/ — Pattern A ONNX + vocab + normalization + parity samples
  • assets/models/pattern_b_dual_branch/ — Pattern B ONNX + vocab + normalization + parity samples

On the phone after a scan:

  • Android/data/.../files/metrics/all_scan_metrics.json — one growing log of all scans

Parity check vs real scans

flowchart LR subgraph A4["A4 — Parity (test)"] P1[8 fixed number sets in app] --> P2[Run ONNX on phone] P2 --> P3{Match PC answers?} end subgraph A3["A3 — Real scans"] R1[Your APKs in Download/] --> R2[Extract features from each APK] R2 --> R3[Run all models + save JSON] end A4 -->|pass first| A3

A4 = quick exam (Android Studio → run three parity tests). A3 = real work (use the app, scan APKs, pull JSON to PC). Run all three A4 tests before trusting thesis scores.

What you see in the app

  • Results table — one row per APK (XGB+CNN ensemble verdict, time, memory)
  • Log panel — all 5 model scores as each APK is processed (XGB, CNN, BM1, Pattern A, Pattern B)
  • Metrics file — detailed JSON with a stages[] list (one entry per model per scan)

Typical stages[] in metrics JSON

one scan entry ├─ stages[0] domain: manifest_xgb → score, parse_ms, inference_ms ├─ stages[1] domain: bytecnn → score, parse_ms, inference_ms ├─ stages[2] domain: dex_header_d3 → BM1 score + timings ├─ stages[3] domain: dex_header_manifest → Pattern A score + timings ├─ stages[4] domain: dex_header_manifest_dual → Pattern B score + timings ensemble block → combined XGB + CNN verdict only

Rules of thumb

  • Put APKs in Download/ — the app scans all of them, not one-by-one picker.
  • Models run on the phone — no internet needed for inference.
  • All 5 models run on every APK in Download — scans take longer than the old 2-model app.
  • Legacy (XGB + CNN) and thesis models (BM1, Pattern A, Pattern B) coexist; missing assets skip that model only.
  • Train on PC → export ONNX → copy into assets/ → rebuild app → re-run A4 → scan on phone.

What you need to manually handle yourself

Everything below happens outside Cursor — on your PC (Android Studio) and your POCO F3. The code is already in the repo; you install and run it.

Order matters: run A4 (all three parity tests) before A3 (real APK scans). A4 checks phone ONNX math in a few minutes — run MlpHeaderParityTest, PatternAParityTest, and PatternBParityTest (8/8 each). Only then scan real APKs and pull metrics.
① One-time phone setup → ② Install app (Run ▶) → ③ A4 parity (BM1 + A + B) → ④ A3 scan APKs → ⑤ Pull JSON to PC

① One-time: phone + cable

1
Enable Developer options on POCO F3
Settings → About phone → tap MIUI/HyperOS version 7 times until it says you are a developer.
2
Turn on USB debugging
Settings → Additional settings → Developer options → enable USB debugging (and Install via USB if you see it).
3
Plug phone into PC
Use a data USB cable. On the phone popup, tap Allow USB debugging → Allow.
Phone notification shade → USB mode → choose File transfer if the PC does not see the device.

② Install VigiDroid (every time code changes)

1
Open the correct folder in Android Studio
File → Open → select thesis_vigidroid/vigidroid (not the repo root). Wait for Gradle sync to finish (progress bar at the bottom).
Android Studio window
Left: Project panel  |  Center: code  |  Bottom: Build / Run tabs
2
Select your phone at the top
In the toolbar, open the device dropdown (next to the green triangle). Pick POCO F3 or M2012K11AG — not "No devices".
[ app ▼ ] [ POCO F3 ▼ ] [ ▶ Run ] [ 🐛 ]
If empty: unplug/replug USB, unlock phone, check USB debugging.
3
Click the green Run button (▶)
Android Studio builds the app, installs it on the phone, and opens VigiDroid automatically. First build can take several minutes.
Bottom Run tab → you should see BUILD SUCCESSFUL then Install successfully finished
4
Grant storage permission on the phone
When VigiDroid opens, allow storage access. If asked for All files access, go to Settings and enable it for VigiDroid — otherwise scans cannot read Download/.

③ A4 — Parity tests (do this before scanning real APKs)

This does not use your APK dataset. Each test runs 8 built-in practice inputs and checks scores match the PC export. Run all three tests after every install that changes models or assets.

1
Phone still plugged in with USB debugging on (same as step ②).
2
Find the test files in the Project panel
Switch the left panel to Project view (dropdown usually says "Android" — change to Project if needed). Expand:
app → src → androidTest → java → com.msh.vigidroid →
  MlpHeaderParityTest  (BM1)
  PatternAParityTest  (Pattern A)
  PatternBParityTest  (Pattern B)
3
Run BM1 parity test
Right-click MlpHeaderParityTest → Run 'MlpHeaderParityTest'.
(This is not the green ▶ Run button for the app — that runs the normal app. Tests are a separate run.)
Bottom panel switches to Run (or Test Results)
✓ paritySamples_matchPcExport — green check = BM1 A4 passed
✗ red line — failed; fix code or re-copy assets/models/mlp_header/ before doing A3
4
Run Pattern A parity test
Right-click PatternAParityTest → Run 'PatternAParityTest'.
✓ paritySamples_matchPcExport — green check = Pattern A A4 passed
✗ red line — failed; fix code or re-copy assets/models/pattern_a_combined/ before doing A3
5
Run Pattern B parity test
Right-click PatternBParityTest → Run 'PatternBParityTest'.
✓ paritySamples_matchPcExport — green check = Pattern B A4 passed
✗ red line — failed; fix code or re-copy assets/models/pattern_b_dual_branch/ before doing A3
6
Pass criteria
All three tests green (8/8 samples each). You do not need to touch the phone screen during this — tests run on the connected device in the background.
Optional terminal (all three in one go, after installDebug):
cd thesis_vigidroid/vigidroid
./gradlew connectedDebugAndroidTest \
  -Pandroid.testInstrumentationRunnerArguments.package=com.msh.vigidroid
Do not skip A4. If any parity test fails, scanning real APKs will produce untrustworthy thesis model scores.

④ A3 — Real scans on the phone

Only after all three A4 parity tests pass.

1
Copy APKs onto the phone
Put every APK you want scanned into Internal storage → Download (not inside the app folder).
  • USB: copy files into the phone's Download folder from your PC file manager
  • Or: adb push myapp.apk /sdcard/Download/ from a terminal
Files app on phone → Internal storage → Download → your .apk files listed here
2
Open VigiDroid on the phone
Tap the VigiDroid icon (installed from Android Studio Run ▶). You do not need USB connected for scanning, but keep it connected if you want to watch logs in Android Studio.
3
Tap Start APK Scan
The app finds all .apk files in Download and scans them one by one.
[ Start APK Scan ] button near the top
Status changes to Scanning…
Log panel shows XGBoost, 1D-CNN, then thesis lines like:
BM1 mlp_header: score=0.87 …
Pattern A: score=0.12 …
Pattern B: score=0.65 …
Results table gets one row per APK (ensemble verdict only)
4
Wait until finished
Status returns to Idle. Metrics are saved automatically to all_scan_metrics.json on the phone (path shown in the app metrics section).

⑤ Pull metrics to your PC

1
Phone plugged in, USB debugging on
2
Run the pull script from the repo root
cd /mnt/Files/thesis_vigidroid
bash Shared_pipeline_Files/tools/pull_device_metrics.sh
Output lands in Shared_pipeline_Files/results/device/ — use this for thesis plots.
3
Alternative: Android Studio Device File Explorer
View → Tool Windows → Device File Explorer → browse to the metrics path on the phone → right-click file → Save As.

Checklist before thesis scans

  • Phone: USB debugging on, storage / all-files access granted for VigiDroid
  • PC: Android Studio opened on vigidroid/, POCO F3 selected, Run ▶ succeeded
  • A4: MlpHeaderParityTest, PatternAParityTest, PatternBParityTest — all green
  • A3: APKs in Download/, tap Start APK Scan, wait for Idle
  • Pull: bash Shared_pipeline_Files/tools/pull_device_metrics.sh → check stages[] has 5 entries per scan
