LinRegDroid — Implementation Plan

Paper: Şahin et al., IEEE Access 2022 · Aligned with Pipeline_full_concept.html (P0–P8 + A1–A4)
Proposed model_id: linregdroid_permission · domain: manifest_permissions · On-device: yes (single dot product + threshold)

Scope & role in thesis

LinRegDroid is an ultra-minimal permission-only baseline: binary permission vector \(\mathbf{p} \in \{0,1\}^M\), multiple linear regression by least squares, then LinRegDroid1 (threshold 0.5) or LinRegDroid2 (nearest class). Optional bagging (Ensemble-1 / Ensemble-2) improves F-measure on AMD in the paper (~0.956 with mixed learners).

This folder is a self-contained Python project under linear/. It does not depend on Dex-header or ASCNN code, but reuses the same corpus layout, temporal split, and metrics JSON conventions as BM1 / Pattern A/B.

Label encoding note: The paper trains MLR with \(y=1\) benign, \(y=0\) malware. Your thesis pipelines use label 0 = benign, label 1 = malware. Implementation must document and apply an explicit mapping at train, eval, and ONNX export time (see §Label mapping).

Do not copy APKs into the repo — manifests only.

P2 — Permission feature extraction

Exit criteria Sharded .npz per APK, frozen permission_vocab.json, failed_apks.log.

Component A implementation

For each APK, extract only <uses-permission android:name="…"> via pyaxmlparser (APK.get_permissions()). No intent actions/categories (unlike Pattern A/B manifest_bow.py).

Vocabulary (train split only)

  1. Scan all train APKs (not val/test); collect unique permission strings \(\mathcal{P}\).
  2. Sort lexicographically for stable index order; save artifacts/permission_vocab.json: { "permissions": [...], "M": 137, "version": 1 }.
  3. At inference: permissions not in \(\mathcal{P}\) are ignored (paper rule).

Per-APK encoding

\[ p_{i,k} = \mathbb{1}[\text{perm}_k \in \text{Manifest}(i)] \]

Store p as float32 vector of length \(M\) (0/1).

Shard layout

artifacts/processed/shards/{split}/{sha256}.npz
  p: (M,) float32
  label: int64 scalar (thesis 0/1)
  sha256: str (optional)

Script chain (scripts/run_preprocess.sh)

  1. scan_dataset.py (if index missing)
  2. build_permission_vocab.py — train APKs only
  3. extract_to_cache.py — all splits using frozen vocab; resume via processed_ids.txt

Failure handling

Unreadable manifest → append to artifacts/failed_apks.log; skip sample. Empty permission list is valid (all-zero vector) — do not treat as failure unless parser throws.

P4 — Model definition

Exit criteria Forward pass: p → ŷ → class matches paper Algorithms 1 & 2.

Component B — MLR

\[ \hat{y}_i = \beta_0 + \sum_{k=1}^{M} \beta_k p_{i,k} \]

Fit via sklearn LinearRegression(fit_intercept=True) on \((\mathbf{X}, \mathbf{y}_\text{paper})\) — equivalent to normal equations \((\mathbf{X}^T\mathbf{X})^{-1}\mathbf{X}^T\mathbf{y}\).

Component C — LinRegDroid1

def predict_class(y_hat: float, threshold: float = 0.5) -> int:
    # returns thesis label: 0 benign, 1 malware
    benign_paper = y_hat >= threshold
    return 0 if benign_paper else 1

Component D — LinRegDroid2

def predict_class_nearest(y_hat: float) -> int:
    c = min((0, 1), key=lambda k: abs(y_hat - k))  # paper encoding
    return 0 if c == 1 else 1  # map paper c to thesis label

PyTorch mirror (for ONNX)

nn.Linear(M, 1, bias=True) with weights copied from sklearn — used only at export/parity, not for gradient training.

Optional — Bagging (bagging_ensemble.py)

  • Ensemble-1: \(B=5\) bootstrap samples of train set; each fits MLR; majority vote on LinRegDroid1 labels.
  • Ensemble-2: Mix MLR, LinearSVC, DecisionTreeClassifier on bootstrap samples; majority vote.

Exit criteria artifacts/checkpoints/linregdroid1.joblib (or .pt mirror) + fitted coefficients JSON.

  1. Load all train shards → \(\mathbf{X} \in \mathbb{R}^{N \times M}\), labels → \(\mathbf{y}_\text{paper}\).
  2. Fit LinearRegression (single model or bagging ensemble).
  3. Save: coefficients, intercept, permission_vocab.json copy, training metadata (N, M, date).
  4. Log top-|β_k| permissions for thesis interpretability table.

Checkpoint contents

No GPU required. Fitting completes in seconds on CPU for thesis-scale data.
