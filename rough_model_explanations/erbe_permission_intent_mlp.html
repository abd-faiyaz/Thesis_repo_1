ERBE Permission + Intent MLP (Base Learner)

Paper: Potha et al., Connection Science 2020 — An extrinsic random-based ensemble approach for android malware detection (ERBE)

Prerequisites

Static manifest features: Permissions (<uses-permission>) and intent actions (<action android:name="…"> in intent filters) — all extractable without running the APK.

Binary feature vector: One dimension per distinct permission or intent string in the training corpus; value 1 if present in APK, else 0 (~1K dims on AndroZoo in paper).

MLP: Multi-layer perceptron — fully connected layers with ReLU and sigmoid output for malware probability.

Ensemble vs deployable: Full ERBE runs 15 iterations with random feature/instance subspaces — best offline, 15× inference cost. Thesis uses one MLP base learner on the full vector.

1. Overview

On AndroZoo-scale corpora, manifest permissions alone miss behavior declared via intents (e.g. BOOT_COMPLETED, SMS_RECEIVED). Potha et al. build a joint binary vector over permissions and intent actions (~1002 dimensions), then propose ERBE (Extrinsic Random-based Ensemble): 15 rounds of training on random feature subspaces and random external malware/benign subsets, aggregating base-learner scores (LR, MLP, or SGD). That ensemble beats single classifiers by up to 5%+ accuracy but costs ~117 minutes training and 15× inference — unsuitable for per-APK on-device scans. Your thesis deploys ERBE's feature space + one MLP (~1K → hidden → 1) for ONNX parity with other manifest-neural models.

Component A — Permission + intent feature extraction

What it analyzes

Union of all uses-permission names and intent action strings appearing anywhere in the APK manifest (AndroZoo static pipeline in paper).

Why this input was chosen

Intents capture declared interaction with the OS (views, broadcasts, services) beyond capability flags. Joint vocabulary ~1K is compact yet richer than permissions-only LinRegDroid.

Step-by-Step Process

  1. Decompile APK to readable manifest (paper: AndroZoo tooling).
  2. Collect every distinct permission name across training set → index set \(\mathcal{P}\).
  3. Collect every distinct intent action string → index set \(\mathcal{I}\).
  4. Form unified vocabulary of size \(D = |\mathcal{P}| + |\mathcal{I}|\) (paper benchmark \(D \approx 1002\)).
  5. For APK \(i\): \(x_{i,j} = 1\) if feature \(j\) present, else 0.

Mathematical Formulation

\[ x_{i,j} = \begin{cases} 1 & \text{if feature } j \in \text{Manifest}(i) \\ 0 & \text{otherwise} \end{cases}, \quad \mathbf{x}_i \in \{0,1\}^{D} \]

Paper example: App1 uses \(p_1,p_2,i_1\) → \((1,1,0,1,0,0)\); App2 uses \(p_1,p_3,i_2,i_3\) → \((1,0,1,0,1,1)\) over joint \((p_1,p_2,p_3,i_1,i_2,i_3)\).

  • \(D\) — total feature dimension (~1002 AndroZoo)
  • \(\mathcal{P}, \mathcal{I}\) — permission and intent vocabularies
  • \(x_{i,j}\) — binary indicator for feature \(j\)

APK → manifest

         └─► intent actions ┼─► x  (1×D)  e.g. 1×1002

Output and how it connects to the next stage

Outputs \(\mathbf{x} \in \{0,1\}^{D}\). Feeds ERBE iterations (paper) or single MLP (thesis).

Key Advantage / Novelty

Key novelty: Single unified manifest vector mixing permissions and intents — simpler than TF-IDF weighted 2500-d deployed XGBoost but same semantic domain.

Component B — Full ERBE ensemble (paper, reference only)

What it analyzes

Binary vector \(\mathbf{x}\) and labeled training pool; external malware/benign repositories for extrinsic sampling.

Why this input was chosen

ERBE injects diversity via random subspaces and external samples so each of 15 base models sees different views — reduces correlation of errors vs bagging on identical features.

Step-by-Step Process

  1. Set iteration count \(T = 15\).
  2. For \(t = 1,\ldots,T\): sample random feature subset at rate \(a\) (e.g. 50% of \(D\)).
  3. Sample random external malware and benign APK subsets (extrinsic data).
  4. Train base learner (LR, MLP, or SGD) on subspace + subset.
  5. Score each test APK; append to list \(\mathcal{S}\).
  6. Aggregate: mean or vote over \(\mathcal{S}\) → final malware score.

Mathematical Formulation

\[ \hat{y}_{\text{final}} = \frac{1}{T}\sum_{t=1}^{T} f_t(\mathbf{x}_{\mathcal{F}_t}), \quad \mathcal{F}_t \subset \{1,\ldots,D\},\ |\mathcal{F}_t| \approx a \cdot D \]

Each \(f_t\) is a base classifier trained on features \(\mathcal{F}_t\) only.

  • \(T=15\) — ensemble iterations (paper)
  • \(a\) — feature sampling rate (~0.5)
  • \(f_t\) — base learner at round \(t\) (ERBEMLP, ERBELR, ERBESGD)
  • extrinsic samples — external APKs added per round for diversity

Architecture Flowchart

x (1×D)
  │
  ├─► round 1: x|F1, external data → f1 → s1
  ├─► round 2: x|F2, external data → f2 → s2
  │      ...
  └─► round 15: x|F15 → f15 → s15
              │
              ▼
        mean(s1..s15) → ŷ_final

Output and how it connects to the next stage

Outputs aggregated malware score. **Not deployed** on-device — reference for why single MLP is chosen.

Key Advantage / Novelty

Why this is different from standard bagging: Random feature subspaces + extrinsic instance injection, not only bootstrap rows on full \(\mathbf{x}\).

Component C — Deployable base MLP (thesis)

What it analyzes

Full (or slightly reduced) permission+intent vector \(\mathbf{x} \in \{0,1\}^{D}\), all features every forward pass.

Why this input was chosen

One forward pass, small weight matrices, exportable to ONNX — matches VigiDroid need for a second manifest-neural model alongside XGBoost.

Step-by-Step Process

  1. Input layer: \(D\) neurons (binary \(\mathbf{x}\)).
  2. Hidden layer: e.g. 128 units, ReLU activation.
  3. Output layer: 1 neuron, sigmoid → \(\hat{y} \in [0,1]\).
  4. Train with BCE loss on labeled APKs.
  5. Threshold 0.5 at inference for malware label.

Mathematical Formulation

\[ \mathbf{h} = \mathrm{ReLU}(\mathbf{W}_1 \mathbf{x} + \mathbf{b}_1), \quad \hat{y} = \sigma(\mathbf{W}_2 \mathbf{h} + \mathbf{b}_2) \]

\(\sigma(z) = 1/(1+e^{-z})\) — malware probability.

  • \(\mathbf{W}_1, \mathbf{b}_1\) — first layer weights ( \(D \times H\) )
  • \(H\) — hidden size (e.g. 128)
  • \(\hat{y}\) — output malware probability

Output and how it connects to the next stage

Outputs \(\hat{y}\) for ensemble fusion with Dex/header models or multistep cascade. ERBE-style 15× averaging reserved for offline ablation.

Key Advantage / Novelty

Key advantage: Captures mild nonlinearity (permission–intent interactions) that linear ERBE base cannot, at single-pass cost.

Why ERBE improved: Different random feature subsets emphasize different permission/intent combinations; extrinsic samples expose the learner to malware families not in the current minibatch — lowers correlated errors when averaged.

Why thesis uses one MLP: Same ~1K semantic signal without 15× latency; ensemble diversity deferred to cross-domain voting (header, bytes, manifest).
